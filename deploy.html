SELF-HOST · YOUR ACCOUNT · YOUR KEYS

Deploy a VibeAgent
you actually own.

Select a model provider, prepare independent credentials, then complete deployment directly on Vercel. This page never asks you to paste API keys and never sends credentials to its server.

01 / Choose your AI provider

You can add another provider later in your own project's environment settings. OpenRouter free is not suitable for confidential scan evidence.

02 / Prepare storage

Hosted scans need durable Redis/Upstash storage before they can run. Provision your own database and obtain:

  • KV_REST_API_URL
  • KV_REST_API_TOKEN

Find a Redis provider in Vercel Storage Marketplace. Upstash REST variable names can be mapped to these keys.

Durable background mode additionally needs a separately hosted worker, and stays disabled until it is configured.

03 / Create private access credentials

Use long independent values for your deployment's scan-access token, workspace-admin token and verification signing secret. Generate and copy these locally, then paste directly into Vercel's environment-variable prompts. Nothing generated here is uploaded or stored.

VIBE_AGENT_API_TOKEN
VIBE_AGENT_WORKSPACE_TOKEN
VIBE_AGENT_VERIFICATION_SECRET

Tokens are generated only when you click; keep them somewhere private. If lost, rotate them in Vercel.

04 / Deploy on your Vercel account

  1. Choose a Vercel team/project you control. Vercel will clone the public repository into your Git account.
  2. Enter the API key for your selected AI provider and the two Upstash credentials, plus the three secrets you generated.
  3. Deploy, then check /api for basic health and /api/capabilities for worker availability. These checks do not validate provider keys or storage. You must redeploy after adding or changing environment variables.
  4. For scans, verify your exact target hostname and supply your own scan authorization token. Do not scan sites you do not own or have permission to assess.

Privacy boundary: This self-deployment does not grant access to the original creator's Vercel team, deployments, environment variables or database. Nor can a copy read your other Vercel projects automatically. Vercel API access would require a separate, explicit, narrowly scoped authorization; this template does not request it.
