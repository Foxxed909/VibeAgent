Platform

Two agents. Local or worker-backed tools. One evidence model.

VibeAgent keeps the autonomous reasoning loop in the standalone product. When worker-tools is enabled, only bounded audit tools execute on the persistent VibeHacking runtime.

AGENT 01

VibeAgent · Discover

Maps cloud edge, routes, APIs, schemas, headers, sessions, auth boundaries and exposed configuration, then follows evidence dynamically.

AGENT 02

BreakAgent · Validate

Uses a narrower validation policy to re-check suspected weaknesses and label confirmed vs unconfirmed results without broad discovery noise.

BACKEND 01

Portable

Serverless-friendly audit tools run directly in VibeAgent with bounded behavior, live SSE events and per-job request context.

BACKEND 02

VibeHacking worker-tools

The standalone agent stays in control while compatible defensive tools execute remotely behind dual exact-host allowlists and ownership verification.

EVIDENCE

Canonical findings

Findings carry severity, validation status, affected URL, evidence, remediation, CWE and OWASP metadata in one shared schema.

WORKSPACE

Runs · Findings · Reports

Open /app to review persisted runs, aggregate findings, reopen threads and download JSON or SARIF reports.

Scope rules (non-negotiable)

VibeAgent never expands beyond the targets you type in.

  • Portable scope never expands beyond the declared hostname; subdomains must be listed separately
  • Worker-tools requires exact server allowlists on both VibeAgent and VibeHacking
  • Worker-backed targets require a one-time /.well-known/vibeagent-verification.txt proof
  • Private invite codes are validated only on the server; no access secret is embedded in the site
  • Cross-origin scan and report access is blocked at the API boundary
